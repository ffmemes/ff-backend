# Пять мемов для друга (H12): реализация

Флаг `FRIEND_CHALLENGE_ENABLED`, по умолчанию выключен. Протокол и пороги:
[2026-09-05-friend-meme-challenge.md](2026-09-05-friend-meme-challenge.md).
Итоги: [`friend-challenge-h12.sql`](../analyst/friend-challenge-h12.sql).

## Путь

1. Обычный лайк в ленте (`handlers/reaction.py`) → `maybe_offer_challenge`.
   Подходящий пользователь (см. протокол) получает назначение в
   `experiment_assignment` (`friend_challenge_h12`, sha256 90% `treatment` /
   10% `holdout`). Проверка подходящести — не чаще раза в сутки (Redis-ключ).
   `treatment` один раз получает предложение; `offer_attempted_at` и
   `offered_at` пишутся в `assignment_metadata`. Также есть команда `/friend`.
2. Автор видит пять кандидатов (сначала свои лайки, затем качественные мемы
   его языков), подтверждает их и получает ссылку `t.me/<bot>?start=fc_<token>`
   с кнопкой «Отправить другу». Подборка фиксируется один раз, редактора нет.
3. Друг по ссылке сразу видит мем 1 из 5 с кнопками «Смешно» / «Не зашло».
   Новому пользователю ставятся языки мемов подборки и `user.inviter_id` =
   автор (та же колонка, что у ссылок на мемы; пишется один раз при
   регистрации, вознаграждение за приглашение не начисляется).
4. После пяти ответов — «Тебе зашли N из 5» и переход в свою ленту.
   Ответы записываются в `user_meme_reaction` с `recommended_by =
   'friend_challenge'` (лайк = 1, «не зашло» = 2, как «следующий мем»),
   не перезаписывая существующие реакции. Поэтому сыгранные мемы не
   повторяются в ленте, а лайки сразу учитываются рекомендациями.
   Прошедший игру (и не назначенный в holdout) может собрать свою подборку.

Holdout никогда не создаёт подборки, но может пройти чужую.

## Таблицы

`friend_challenge_pack` (автор, токен, `confirmed_at`), `friend_challenge_item`
(5 фиксированных слотов), `friend_challenge_participation` (старт/завершение),
`friend_challenge_answer` (первый ответ на позицию). Миграция `a7c9e2f5b8d1`.

## Запуск и остановка

1. Применить миграцию, выкатить с выключенным флагом.
2. Проверить в тестовом боте между двумя аккаунтами: создание, подтверждение,
   чужая ссылка, пять ответов, лента, повторный старт, своя ссылка.
3. Включить `FRIEND_CHALLENGE_ENABLED=true`. Назначения появляются при
   добровольной активности, рассылок нет.
4. Читать воронку еженедельно, решение — на день 28 (kill-критерии в протоколе).

Остановка: выключить флаг. Ссылки `fc_` тогда ведут в обычный онбординг/ленту.
Таблицы и назначения удалять не нужно.

## Известные ограничения

- Ответы в игре попадают в `user_meme_reaction` и, значит, в агрегаты
  `meme_stats`; метка `friend_challenge` позволяет их отфильтровать.
- Новый приглашённый определяется по `user.inviter_id` и `user.created_at`
  после назначения отправителя; нативные пересылки без перехода по ссылке
  не видны.
