# CEO Plan: Crossposting Source-Quality Iteration (Phase 2)

Generated by /plan-ceo-review on 2026-04-28
Branch: production | Mode: SELECTIVE (iteration on prior plan)
Repo: ffmemes/ff-backend
Predecessor: 2026-04-12-channel-growth-optimization.md (status: complete — measurement infra deployed, 16 days of baseline collected)

## Problem framing

User goal: maximize forwards (reposts) on TG public channels @fastfoodmemes (RU) and @fast_food_memes (EN) to drive subscriber growth. Forwards are the primary virality signal — a forward = someone shares with friends = potential new bot users.

Validated finding from Phase 1 (do not relitigate):
> Bot engagement signals (likes, lr_smoothed, engagement_score) have r ≈ 0.03–0.04 with channel forwards. Real predictors are source quality + media type. Current ranker SQL is bot-engagement-centric → suboptimal for channel growth.

## Decisions made this review

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Ship source-quality coefficient FIRST (defer VK measurement) | TG RU is main growth channel; data ready; VK collector is M effort that delays main lever |
| D2 | Source quality metric = `AVG(forwards * SQRT(views / 100))` per source (per-post agg, fixed post outside-voice) | Avoids fwd/1k denominator trap (video boost lesson); rewards reach + virality jointly |
| D3 | Add diversity cap ≤1 post/source/24h alongside the boost | Prevents top-source concentration repeating the video-boost concentration failure |
| D4 | Roll EN + RU simultaneously, with `m.type='image'` filter in source-quality CTE | RU baseline is short (2 days clean) but image-only filter mitigates; neutral fallback (coef=1.0) for sources with n<5 |

## Implementation shape

In `src/crossposting/service.py`, both `get_next_meme_for_tgchannelru` and `get_next_meme_for_tgchannelen`:

```sql
WITH src_quality AS (
    SELECT
        m.meme_source_id,
        AVG(latest.forwards) AS avg_fwd,
        AVG(latest.views) AS avg_views,
        COUNT(*) AS n_posts
    FROM (
        SELECT DISTINCT ON (cps.channel, cps.telegram_message_id)
            cps.channel, cps.telegram_message_id, cps.meme_id,
            cps.forwards, cps.views, cps.snapshot_at
        FROM crossposting_snapshots cps
        WHERE cps.channel = :channel
          AND cps.snapshot_at > NOW() - INTERVAL '30 days'
          AND cps.views > 0
        ORDER BY cps.channel, cps.telegram_message_id, cps.snapshot_at DESC
    ) latest
    JOIN meme m ON m.id = latest.meme_id
    WHERE m.type = 'image'   -- exclude video-era confound
    GROUP BY m.meme_source_id
    HAVING COUNT(*) >= 5
),
recent_src AS (
    -- diversity cap: ≤1 post per source per 24h
    SELECT DISTINCT m2.meme_source_id
    FROM crossposting cp2
    JOIN meme m2 ON m2.id = cp2.meme_id
    WHERE cp2.channel = :channel
      AND cp2.created_at > NOW() - INTERVAL '24 hours'
)
SELECT M.id, M.type, M.telegram_file_id, M.caption
FROM meme M
INNER JOIN meme_stats MS ON MS.meme_id = M.id
LEFT JOIN crossposting CP ON CP.meme_id = M.id AND CP.channel = :channel
LEFT JOIN src_quality SQ ON SQ.meme_source_id = M.meme_source_id
WHERE 1=1
  AND CP.meme_id IS NULL
  AND M.status = 'ok'
  AND M.language_code = :lang
  AND M.type = 'image'
  AND MS.nlikes >= 5
  AND M.meme_source_id NOT IN (SELECT meme_source_id FROM recent_src)
ORDER BY -1
    * COALESCE((MS.nlikes + 1.) / (MS.nlikes + MS.ndislikes + 1), 0.5)
    * CASE WHEN MS.raw_impr_rank <= 1 THEN 1 ELSE 0.8 END
    * CASE WHEN MS.age_days < 7 THEN 1 ELSE 0.8 END   -- 7 for RU, 90 for EN (keep current per-channel)
    * CASE WHEN M.caption IS NULL THEN 1 ELSE 0.8 END
    * CASE
        WHEN MS.nmemes_sent <= 1 THEN 1
        ELSE (MS.nlikes + MS.ndislikes) * 1. / MS.nmemes_sent
      END
    * COALESCE(
        LEAST(2.0, GREATEST(0.5,
            (SQ.avg_fwd * SQRT(SQ.avg_views / 100.0)) / NULLIF(:median_signal, 0)
        )),
        1.0
      )
LIMIT 1
```

`:median_signal` = ~30 for EN, ~50 for RU (calibrate from current data; document final values in PR).

`score_version=2`. Bump in `log_meme_sent` call.

### Codex outside-voice triage (final disposition after user product-principle correction)

**REJECTED — codex #1 (lower nlikes gate):** Channel premise is "best of bot", not "newest of source". Bot-engagement gate is the **quality floor feature**, not a bug. Phase 1's r=0.03 means bot signal alone doesn't predict forwards — it does NOT mean bot signal is useless as a quality filter. Keep `nlikes >= 5`. Source-quality re-ranks **within** bot-approved subset.

**ACCEPTED — codex #2 (fix success query):** Original SQL didn't segment v1-era vs v2-era. Replacement below uses `v2_ship` CTE + 48h maturity filter (also picks up codex #3 free).

**ACCEPTED — codex #7 (rebuild CTE from crossposting, not snapshots):** Stats collector already denormalizes latest views/forwards into `crossposting` row. Simpler, faster (PK covers query), easier to test.

**ACCEPTED — codex #8 free (per-post aggregate vs product-of-averages):** `AVG(forwards * SQRT(views))` is correct, not `AVG(fwd) * SQRT(AVG(views))`.

**NEW — add `invited_count` to ranker (user product principle):** `meme_stats.invited_count` (in-bot shares via `s_{user_id}_{meme_id}` deep links, populated hourly by `calculate_meme_invited_count`) is a direct virality signal — user shared the meme, friend opened it. Add as ranker multiplier. Channel-post share clicks (`sc_%` deep links) require schema change to materialize in meme_stats — deferred (see TODOS).

### Final SQL shape (source ranker)

```sql
WITH src_quality AS (
    SELECT
        m.meme_source_id,
        AVG(cp.forwards * SQRT(GREATEST(cp.views, 1) / 100.0)) AS signal,
        COUNT(*) AS n_posts
    FROM crossposting cp
    JOIN meme m ON m.id = cp.meme_id
    WHERE cp.channel = :channel
      AND cp.created_at > NOW() - INTERVAL '30 days'
      AND cp.created_at < NOW() - INTERVAL '48 hours'   -- mature only (codex #3)
      AND cp.views IS NOT NULL
      AND cp.views > 0
      AND m.type = 'image'
    GROUP BY m.meme_source_id
    HAVING COUNT(*) >= 5
),
src_median AS (
    SELECT PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY signal) AS m_signal
    FROM src_quality
),
recent_src AS (
    SELECT DISTINCT m2.meme_source_id
    FROM crossposting cp2
    JOIN meme m2 ON m2.id = cp2.meme_id
    WHERE cp2.channel = :channel
      AND cp2.created_at > NOW() - INTERVAL '24 hours'
)
SELECT M.id, M.type, M.telegram_file_id, M.caption
FROM meme M
INNER JOIN meme_stats MS ON MS.meme_id = M.id
LEFT JOIN crossposting CP ON CP.meme_id = M.id AND CP.channel = :channel
LEFT JOIN src_quality SQ ON SQ.meme_source_id = M.meme_source_id
WHERE 1=1
  AND CP.meme_id IS NULL
  AND M.status = 'ok'
  AND M.language_code = :lang
  AND M.type = 'image'
  AND MS.nlikes >= 5                              -- KEPT (quality floor for "best of bot")
  AND M.meme_source_id NOT IN (SELECT meme_source_id FROM recent_src)
ORDER BY -1
    * COALESCE((MS.nlikes + 1.) / (MS.nlikes + MS.ndislikes + 1), 0.5)
    * CASE WHEN MS.raw_impr_rank <= 1 THEN 1 ELSE :impr_penalty END
    * CASE WHEN MS.age_days < :age_threshold THEN 1 ELSE 0.8 END
    * CASE WHEN M.caption IS NULL THEN 1 ELSE 0.8 END
    * CASE
        WHEN MS.nmemes_sent <= 1 THEN 1
        ELSE (MS.nlikes + MS.ndislikes) * 1. / MS.nmemes_sent
      END
    * COALESCE(                                   -- source-quality multiplier
        LEAST(2.0, GREATEST(0.5,
            SQ.signal / NULLIF((SELECT m_signal FROM src_median), 0)
        )),
        1.0
      )
    * (1.0 + LEAST(MS.invited_count, 10) * 0.1)   -- in-bot share boost (NEW): up to 2x at 10+ shares
LIMIT 1
```

Per-channel params: `:impr_penalty` = 0.8 RU / 0.5 EN; `:age_threshold` = 7 RU / 90 EN.

`invited_count` boost: linear up to 10 shares (cap), so a meme with 10+ in-bot shares gets ×2 multiplier. Most memes have 0 invites, so this is asymmetric — only **proven-shared** memes get the boost, rest are neutral (×1.0).

### Fixed success measurement query

```sql
WITH v2_ship AS (
    SELECT MIN(created_at) AS d FROM crossposting WHERE score_version = 2
)
SELECT
    score_version,
    channel,
    AVG(forwards) AS avg_fwd,
    AVG(views) AS avg_views,
    AVG(reactions) AS avg_react,
    COUNT(*) AS n
FROM crossposting cp, v2_ship
WHERE views IS NOT NULL
  AND created_at < NOW() - INTERVAL '48 hours'
  AND (
        (score_version = 2 AND created_at >= v2_ship.d)
     OR (score_version = 1 AND created_at < v2_ship.d
                          AND created_at >= v2_ship.d - INTERVAL '14 days')
      )
GROUP BY score_version, channel
ORDER BY channel, score_version;
```

Pass: avg_forwards (v2) ≥ 1.15× avg_forwards (v1) on at least one channel, no >10% drop in avg_views. Run after v2 has been live ≥ 14 days post-ship.

## Failure modes & mitigations

| Failure | Detection | Mitigation |
|---------|-----------|------------|
| Single source dominates window despite cap | Daily SQL: `SELECT meme_source_id, COUNT(*) FROM crossposting WHERE channel=X AND created_at > NOW()-7d GROUP BY 1 ORDER BY 2 DESC LIMIT 5` | Cap is hard NOT IN clause — diagnostic if violated means a source is reposting under a different meme_source_id |
| Coefficient bounds (0.5/2.0) too tight or loose | A/B versions: filter score_version=2 last 14d, compare avg_fwd vs score_version=1 last 14d before this | Adjust clamp constants in next PR |
| RU sources with insufficient image-history all get neutral 1.0 | RU baseline gets noisy first 2 weeks | Accepted tradeoff — measurement continues, can re-roll RU after 2026-05-12 with clean image-only data |
| Channel reach degrades (the video-boost trap repeated) | Telethon collector continues; weekly: avg_views/post by score_version | Rollback: revert PR, score_version stays at 2 in DB so future versions are 3+ |

`git revert` the PR. The `score_version` column allows post-mortem comparison without reverting data. Rollback is one-way-door-light (versioned data preserved).
